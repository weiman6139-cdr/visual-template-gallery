# Visual Template Gallery

当用户调用带模板的图片 Skill，或明确要求浏览模板、选择模板、查看模板示例时使用此 Skill。

## 工作流

1. 确认当前 Skill 的本地路径。
2. 从项目根目录启动图库服务：

```bash
npm run dev -- --skill "<当前 Skill 路径>"
```

3. 使用输出地址中的 `embed=1` 紧凑模式；在 Codex Desktop 中优先调用 `mcp__codex_app__open_in_codex`，将该本地 URL 作为 browser target、placement 设为 `right`，让图库显示在 Codex 面板内。若宿主不提供该工具，再回退到浏览器打开地址。
4. 用户可以翻页查看完整模板列表，按分类或关键词筛选，并单选或多选。
5. 用户点击“加入选择”后，图库会自动把选择同步到当前图库会话；不要求用户复制模板上下文。
6. 用户回到 Codex 对话框描述需求时，读取图库会话的 `/api/selection` 和 `/api/context`，将已选模板作为当前请求的视觉参考上下文。
7. 结合用户需求，调用当前 Codex 可用的生图或网页制作能力；不要默认绑定 `sheng-tu`。

## 规则

- 优先展示 Skill 关联 GitHub 仓库已有的官方示例图，不为预览阶段重新生图。
- 不替用户自动推荐三个模板；除非用户明确要求推荐，否则展示完整模板库。
- 选择多个模板时，保持每个模板的独立来源和参考图信息。
- 当前模型支持图片参考时，优先将选中示例图作为参考；只支持文字时，使用模板指导和标签降级生成。
- 没有可用生图 Provider 时，明确告诉用户需要配置能力，不伪造生成结果。
- 当前 Codex 宿主没有公开的 composer 写入接口，因此“自动同步”通过本地图库会话完成；不要声称已向输入框插入了不可见消息。
