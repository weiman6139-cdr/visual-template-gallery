# ADR-0004：MCP App 插件与被动对话参考


> **状态：历史文档（已被取代）。** 本文件描述的是 MCP App 面板方案。本目录已改为纯网页端（浏览 + 复制模板名称），面板能力保留在上游项目。现行方案见 [2026-10-29 网页端方案](../plans/2026-10-29-web-only-plan.json)；替代决策 ADR-0005 待补。

状态：Accepted，2026-10-16。替代 ADR-0001 的主交付定位；原 Web 实现仅保留在历史文档，不作为运行入口。

## 背景

用户的核心诉求是插件内看到全部模板，点击选择后继续在当前对话描述任务。将默认交付改成 Skill 启动 localhost 网页、选择仅保存在本地服务，会偏离目标；不能修改验收以掩盖差距。

## 决策

以 Codex 插件注册自包含 stdio MCP Server，提供 ui:// MCP App 资源。模型显式调用打开目标模板 Skill 全库，宿主承载应用；选择由应用通过 ui/update-model-context 提交为被动参考。Skill 仅提供模型工作流说明，不是 UI/同步实现。

优先复用 GitHub 官方示例、已有解析与缓存。图库不生图、不主动发送消息。后续任务按宿主当前工具执行，不绑定 sheng-tu。第一阶段只做 Codex，避免提前增加通用适配层。

## 权衡与验收

MCP App 使用 HTML，区别在插件协议与宿主承载，而不是要求用原生 UI 语言重写。没有已验证的任意 Skill 事件监听或 composer 可见注释接口，当前触发通过显式工具调用；模型参考不冒充可见附件。

协议支持不保证当前 Codex 第三方插件支持。必须验收实际 App 展示、updateModelContext 能力及下一条用户任务读取相同模板。缺少能力时保持目标未通过，不退回 Web 定位并称完成。

## 影响与回滚

新增 MCP 服务、App 和打包；删除旧 HTTP/Provider 和旧 Web 资源，避免端口与入口冲突。更新独立 Skill 避免回退网页，保留历史原文备份。卸载插件即可停用新入口，无需修改 Codex 应用安装文件。
