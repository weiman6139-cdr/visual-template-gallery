## 目标与成功标准

用户调用带模板的 Skill 时，在 Codex 右侧扩展面板看到完整模板库及 GitHub 官方示例，手动选择一个或多个模板；选择成为后续对话参考，用户直接描述任务，无需来回复制提示词。第一阶段只实现 Codex，其余 Agent 后续适配。

当前开发路径为插件注册 MCP 服务，模型显式调用打开图库，宿主承载 MCP App。Skill 是集成说明，不能成为实际唯一入口；localhost 浏览器不能充当默认插件面板验收证据。选择通过宿主的 `ui/update-model-context` 提交。实际接收须真实 Codex 验证。

## 用户流程

```text
调用模板 Skill / 请求浏览模板
→ 模型调用 open_template_gallery（目标 Skill 路径）
→ MCP App 连接后请求展开，Codex 右侧展示图库
→ 分页浏览官方示例、选择一个或多个模板
→ 更新模型参考上下文，显示宿主回执状态
→ 用户在对话框描述任务
→ 模型结合目标 Skill、所选模板和用户需求执行
```

不自动发送用户消息，不因打开或选择而生成图片。清空或切换图库需替换旧参考。失败时保留选择并提供重试，不能显示“已同步”。

## 面板要求

- 默认展示全部可解析模板，每页 12 张，搜索、分类筛选、页码跳转。
- 显示名称、ID、分类、标签、官方示例、来源和详情。
- 支持单选、多选、跨页保留、移除、清空。
- 官方图片渐进加载、缓存、来源回退与失败重试。
- 参考提交状态可见：待同步、同步成功、失败可重试。
- 狭窄面板可滚动，不依赖外部浏览器，也不包含生图按钮。
- 自动请求宿主展开；提供手动重试。实际必须位于右侧且对话可输入，对话内卡片或全屏覆盖不算达到目标。

## 输入与参考数据

最低资料需求为模板名称或 ID，以及与其对应的 GitHub 示例图；不强制作者适配专用 JSON。解析现有 Markdown/HTML/常见字段，兼容 manifest 和 theme。资料不完整时显示告警或文字卡片，不编造预览。

上下文包括 Skill 路径、模板 ID、名称、分类、标签、指导文字、来源及参考图候选。它是参考数据，不是高权限指令；不替代用户任务。图片任务优先使用当前宿主能力，缺少能力再说明配置要求，不能固定绑定 sheng-tu。

## 能力边界与验证要求

MCP App 是宿主承载的 HTML 应用；面板位置由宿主控制，不等于原生 UI 组件。模型参考同步不等于 composer 上方可见注释。任意 Skill 的自动监听与可见附件仍是未验证的宿主扩展需求；当前已确认的实现路径使用显式工具调用，不冒称自动监听。

边界不能把核心验收降级为 Web 原型。插件面板和真实后续对话参考必须通过，才算本阶段完成。宿主能力缺失须记录具体阻塞并保留目标。
