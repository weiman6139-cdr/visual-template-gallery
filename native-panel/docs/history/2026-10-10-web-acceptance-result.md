## 4. 功能验收结果

### 已通过

- 能读取 `gpt-image-2-style-library` 的完整模板索引。
- 实际识别 22 个模板，每个模板包含 ID、名称、分类和提示词指导。
- 预览图直接来自 Skill 关联 GitHub 仓库，不在预览阶段重新生图。
- 支持 GitHub Raw 和 jsDelivr 回退，并将成功资源写入本地缓存。
- 图库默认每页 12 个模板，支持搜索、分类筛选、翻页、单选和多选。
- 跨页选择状态按模板 ID 保留。
- 上下文负载包含模板 ID、名称、分类、标签、模板指导、来源和参考图候选。
- 无图片模板仍可通过文字指导参与后续对话。
- Provider 路由未把 `sheng-tu` 写死为核心协议；当前本地默认注册的是 Nopaper 适配器，但服务目前尚未接入 Codex 原生图片工具自动发现。
- Provider 优先级会优先选择支持图片参考的可用实现；仅文本实现会收到去除图片路径后的请求；失败时尝试下一实现。
- Provider 可声明最大参考图数量，超出部分不会静默传递；生成结果展示实际使用数量。
- 旧版 UI 曾要求用户显式点击“生成图片”才发起生图；该入口已从当前图库 UI 移除，生图由后续对话工作流决定。
- 已真实验证一次 Nopaper 生成：结果为冒险地图游戏界面，包含地图主体、阶段拆解、图例和界面标注；视觉结果可正常打开。
- 输出和模板参考图限制在图库缓存目录；HTTP 请求不能通过变更参数切换服务所绑定的 Skill。
- Skill 原文件不会被图库服务修改。

### 未纳入本轮通过范围

- 更多真实 Nopaper 生成样本、不同尺寸/质量和长期稳定性未验收；本轮只验证一次用户授权的默认配置请求。
- Codex 原生右侧栏注入。当前实现是本地 Web 伴随面板，不是原生插件 UI。
- Codex 当前会话/composer 注入。当前选择只写入图库服务内存，需显式后续工作流读取 `/api/context`。
- 任意模板 Skill 调用监听。当前必须通过图库 Skill 或启动脚本进入，不能自动拦截其他 Skill。
- Claude Code、Trae、Cursor 的宿主适配。
- 真实手机设备上的布局和触控实测；当前完成的是 Chrome 设备视口模拟。

## 5. 已知限制

1. GitHub 图片依赖网络和外部仓库路径稳定性；缓存只能缓解已经成功下载的资源。
2. 当前模板解析以 `manifest.json` 和 Markdown 约定为主，格式明显偏离约定的 Skill 可能产生解析告警或漏项。
3. 当前服务默认只注册 `sheng-tu` 适配器；新增其他生图模型需要实现 `ImageProvider` 并注册到 Router。
4. `sheng-tu / Nopaper` 的编辑脚本只接受单张参考图。选中多项时所有文本指导进入提示词，但该 Provider 只使用首张可用示例；支持多参考图的 Provider 可以消费所有图。
5. Codex 目前没有可直接使用的原生右侧栏扩展接口，因此不能宣称已完成原生侧栏插件。
